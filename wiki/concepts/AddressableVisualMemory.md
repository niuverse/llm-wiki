# 可寻址视觉记忆

**可寻址视觉记忆（addressable visual memory）指把智能体看到的原始视觉观测保存在模型上下文之外，用模型能复述的地址索引，并允许它在推理中主动取回、裁剪、放大与测量的机制。** 它与“把图片留在对话里”不是一回事：留在上下文里的图会被压缩、淘汰、按固定预算编码；可寻址记忆把“历史”变成外部存储，上下文只保留当前视图和模型主动取回的那一块。主要证据来自 [[vista-a-visual-harness-for-reasoning-in-an-interactive-world|VISTA]]，工程实现在 [[joshhhhhan-vista-repository|其官方仓库]]。

## 它解决的是三个不同的问题

| 问题 | 表现 | 可寻址记忆的应对 |
| --- | --- | --- |
| 编码时不可知未来用途 | 一张图进入模型时被压成一份表示，十步后需要的细节可能已被丢掉 | 原始观测不进入编码器，需要时再取原图重新裁剪 |
| 上下文容量与淘汰 | 长程交互中早期观测被删除或被文本摘要替代，保留什么由 harness 决定 | 历史不占上下文；淘汰策略与证据保存解耦 |
| 每张图 token 预算固定 | 整幅画面平均到每个格子的 token 极少，细小标记看不清 | 裁出感兴趣区域再放大，把同一份预算集中到少数格子上 |

第三点最容易被忽略。视觉编码器对一张图分配的 token 数大致固定，所以“放大”本身不产生信息；**裁剪才改变有效分辨率**。这解释了一个反直觉的实验结果：把 64×64 棋盘放大 4 倍（256×256，约 77 个图像 token）与放大 8 倍（512×512，约 308 个）效果相当，而放大 16 倍没有额外收益。分辨率不是瓶颈，能否把预算重新分配到当前问题上才是。

## 机制由五层组成

```mermaid
flowchart LR
  E["环境返回帧"] --> S["存储层：原样落盘"]
  S --> I["索引层：turn / frame / region"]
  I --> R["检索层：取帧、裁剪、放大、读像素"]
  R --> M["模型推理"]
  M -->|需要更多证据| R
  M --> B["计量层：图像块与 token 预算"]
  B -->|接近上限| H["交接层：写笔记、换上下文"]
  H --> M
```

- **存储层**保存原始观测，不做重编码；对渲染结果而言是“无损”的。
- **索引层**给出短地址：回合号、帧号、矩形区域。短地址很重要，因为模型要能在推理中复述它；`(turn 128, frame 2, region 40×40)` 比一段图像描述更稳定。
- **检索层**提供多种粒度：整帧回看、区域放大、精确像素测量、动作历史。粒度不齐时，模型会在“看不清”和“说不准”之间被迫猜。
- **计量层**在交付路径上数图像块数或 token，而不是在 prompt 里写“请注意上下文”。
- **交接层**在预算耗尽前把判断写进有长度上限的笔记，然后换一个干净上下文，记忆本身不受影响。

## 证据：收益来自“可检索”，不是“给得多”

VISTA 在 ARC-AGI-3 上的逐层消融给出了一条清晰的曲线：加笔记到 70.05，加无损记忆与 `inspect` 到 94.10，加精确像素读取到 99.00。关键对照是配置 (iv) 与 (v)：前者每次动作自动收到最多 7 帧，后者只收最后一帧，分数却跳了 24 分。信息量减少了，可检索性增加了。

另一个方向也一致：把图像换回文本网格，分数只掉 2.25（99.00 → 96.75），但每局 token 从 30.7M 涨到 71.9M。视觉观测的主要优势是 token 效率；真正的能力增益来自记忆与检查这套接口。

## 设计规则

1. **地址要短，且可用范围要回报。** 每次动作后告诉模型本次归档了几帧、帧号范围，它才知道能取什么；否则模型会假设“只有最后一帧”。
2. **一次检索允许多个视图。** 单视图调用会让模型在“看这里还是看那里”之间反复，成本高且容易放弃。
3. **放大不要平滑。** 最近邻放大保持像素身份；双线性会让颜色边界产生中间色，而颜色本身可能就是语义。
4. **测量与解释分开。** 像素读取只返回数值与符号表，解释留给语言推理；把两者混在一个“视觉问答”工具里，错误会互相掩盖。
5. **记忆存证据，笔记存判断。** 帧是事实，`GUIDE.md` 是当前最佳解释；后者可以错、可以改，前者不应被摘要覆盖。
6. **交接要有协议。** 让模型写有上限的交接文档，再由 harness 换上下文；不要把压缩交给 provider 的隐式摘要。

## 失效情形

- **地址漂移。** 界面布局、分辨率或渲染方式一变，旧坐标失效；记忆里存的是像素，不是对象身份。VISTA 用固定 512×512 显示坐标系规避，但这在真实软件里很难保证。
- **存储无界。** 一局 ARC 游戏可积累 1,472 帧；磁盘不是问题，问题是没有索引策略时模型不知道去哪找。地址可用不等于可发现。
- **模型不用工具。** 检索策略没有被训练，完全依赖模型的主动性；换一个不擅长调用工具的模型，收益会明显缩水（GLM-5.3 Flash 的 66.93 是一个提示）。
- **过度放大丢上下文。** 只看局部会失去全局关系；实践中需要同时保留整帧与裁剪两个尺度。
- **“无损”名不副实。** 若观测通道本身有损（压缩视频、噪声相机），保存原始帧只是保存了有损输入，不能声称证据完整。

## 与相邻概念的关系

- 对 [[AgentHarness|Agent Harness]]：那里区分“会话历史、模型上下文、执行状态”；可寻址视觉记忆是把“历史”留在上下文之外的一种具体做法，且检索单位是像素区域而非文本片段。
- 对长任务上下文管理（[[anthropic-long-running-harness|Anthropic 长任务方案]]）：两者都靠“交接文档 + 新上下文”跨窗口，区别是这里的关键证据不在文档里，而在可按坐标回看的图像里。
- 对 [[RobotHarness|机器人 Harness]]：视觉记忆可用于操作复盘与证据追溯，但物理状态不可回滚——回看一段视频能解释失败，不能撤销失败。

## 待验证的问题

- 能不能学一个检索策略，而不是靠模型即兴决定看哪里？
- “无损”与“可发现”能否兼得：是否需要关键帧索引、对象级索引或时序摘要来辅助寻址？
- 当观测是连续视频流而不是离散帧时，地址应该怎么设计？
- VISTA 用语言推理替代了程序化的世界模型；这种替代在需要精确计数、守恒或长链因果的任务上边界在哪里？
