# 多模态模型的空间工作区

**一句话：模型内部可能存在一个低维、线性、可读可改的空间表示；空间推理的失败既可能来自“没看见”，也可能来自“看见了但不会变换”。** [[s-space-spatial-workspace-mllm|S-Space]] 把前者变成可测量的坐标，把后者变成可分离的计算错误。

## 线性读出假设

对物体名 token 在中间层的表示 $h_{\ell,t}\in\mathbb{R}^{d}$，假设它的视点中心坐标线性编码在三个方向上：

$$
x=v_x^\top h_{\ell,t},\qquad y=v_y^\top h_{\ell,t},\qquad z=v_z^\top h_{\ell,t}.
$$

$x,y$ 是图像平面坐标，$z$ 是距离（深度）。方向 $v_g$ 不是训练出来的探针，而是从模型自己的判断里反推：给定成对问题“A 在 B 左边还是右边”，取最终答案的 logit 差 $s_p$，对两个物体 token 的激活求梯度，用角色反对称差消去共享成分，再归一化并对模板/顺序平均：

$$
v_g=\operatorname{unit}\!\left(\mathbb{E}_p\left[\frac{\nabla_{h_{\ell,q}}s_p-\nabla_{h_{\ell,r}}s_p}{2}\right]\right).
$$

这与“训一个线性分类器探测坐标”不同：方向来自模型输出对内部激活的局部敏感度，因此更接近“模型自己在用哪个方向”，而不是“外部探针能否解码”。

## 三类证据

1. **可读**：投影坐标与真实位置相关；成对坐标差与真实相对位置相关；直接用坐标符号回答空间关系，准确率与模型直接生成相当，甚至在原生空间能力弱的模型上更高（Qwen3.5-4B 的 CV-Bench 73.60→89.36）。
2. **因果**：沿某个轴把物体 token 的激活移动到反事实坐标，保持正交分量不变，模型的空间回答会按预期翻转（左→右、上→下、近→远），而颜色等非空间判断基本不变。这把“相关”推进到“干预”。
3. **持久**：换 prompt 结构（单物体、非空间、多视角）后，同一套固定读出仍有效；多视角下 prompt 可以指定哪个视角作为参考系，水平/垂直 steering 准确率很高，但深度 steering 接近随机。

## 它解释了什么

**感知与计算的分离。** 如果模型答错视角变换题，可能是坐标读错，也可能是坐标对了但旋转错。S-Space 允许先读出坐标、再显式施加视角旋转，从而把两者拆开。SpinBench 上，显式旋转读出把 Molmo2-ER 从 60.96 提到 94.52，把 Qwen3.6-27B 从 60.96（思维链 83.56）提到 95.21；即使把正确前提喂进去，直接回答仍会错，而读出接近满分。这说明**内部坐标已经足够好，瓶颈在变换与读出接口**。

**参考系耦合。** 模型常把图像相对方向当基本方位（右=东、上=北），于是把“东北”答成“北”。从思维链里读 `east`/`north` 的坐标，能看到它们与 `right`/`above` 在 S-Space 中重合。这不是“没有空间表示”，而是**表示里的参考系没有解耦**。

**训练如何塑造表示。** 语言监督把物理与抽象概念混进同一几何（政治左右也落在水平轴上）；动作监督让局部几何更贴近可操作关系（InstructPart 的部件—整体深度判断从 63.1%→67.1%→69.0%）。这支持“表示由预测压力组织出来”，但也说明它不干净：语义先验会污染物理判断。

**测试时演化。** 思维链会让坐标逐步向目标视角旋转，但不完美；更多视角/语言前提会细化坐标，但深度参考系很难被 prompt 重锚定。

## 成立需要哪些假设

1. **线性假设**：坐标可由一个低维线性子空间表示。非线性编码、分布式编码或多子空间并存时，单一读出会漏信息。
2. **层选择可迁移**：每个模型的最佳层不同（Molmo2-ER L22、MolmoAct2 L18/19、Qwen3.5-4B L15、Qwen3.6-27B L43）；跨模型比较必须带层选择，不能把“最佳层”的结果当成任意层都成立。
3. **读出方向稳定**：方向由有限模板与数据估计；换数据集、语言、视角分布后是否仍是同一方向，需要外部验证。
4. **干预局部性**：编辑一个物体 token 的坐标，不应破坏其他信息。论文用颜色判断与未针对的空间判断做检查，但大幅度编辑仍可能波及。

## 常见失败情形

- **把“可解码”当“在使用”**：线性探针能读出坐标，不代表前向计算真的依赖它；需要因果干预。
- **把“表示有”当“模型会用”**：强模型的直接回答可能已经很好，读出未必更好；S-Space 的价值在诊断，不在替代。
- **图像平面坐标当世界坐标**：$x,y$ 没有解耦透视与深度；对成对比较够用，对 3D 重建/操作不够。
- **基准饱和**：Molmo2-ER 在 CV-Bench 94.40、SpatialTunnel 97.83，剩余差异方差未报告；提升可能来自“原生读出接口弱”，而非“表示更好”。
- **语义污染**：政治左右、地图方位与物理方向共享几何；把 S-Space 当“纯空间读数”会带入语言先验。

## 实践含义

1. **先做感知—计算分解**：在骂模型“空间推理差”之前，先读出它的坐标，看是坐标错还是变换错。
2. **用干预验证因果**：只做相关性/探针不够；沿方向编辑，看输出是否按预期改变，非目标判断是否保持。
3. **把读出做成工具**：如果坐标足够准，可以把“读坐标 + 显式几何运算”作为外部工具，而不是强迫模型在语言里做全部变换。
4. **报告层与数据**：任何 S-Space 结果都要带模型、层号、识别数据与读出模板；否则不可复现。
5. **别把可解释当可改进**：目前没有训练时用 S-Space 读出做辅助损失、再测空间推理提升的闭环实验；这是下一步。

## 与库内工作的关系

S-Space 是“世界模型作为**内部表示**”的一侧，[[code-as-world-executable-world-representations|Code-as-World]] 是“外部可执行表示”的一侧：一个问模型心里有没有地图，一个问能不能把地图写成可运行代码。两者都指向 [[ExecutableWorldRepresentation|可执行世界表示]] 的核心——表示是否可操作、可验证；S-Space 提供“读与改”的接口，Code-as-World 提供“写与跑”的接口。评测侧的相关讨论见 [[AgentifiedEvaluation|智能体化评测]] 与 [[WorldModelEvaluation|World Model 评测]]。
