# Overview（总览）

这个页面是 wiki 的 research dashboard。它不按 ingest 顺序复述 source，而是维护当前知识库支持的研究判断、关键问题、证据强弱和后续缺口。完整问题索引见 [[research-questions|Research Questions]]。

## 当前总判断

当前 wiki 的中心判断是：robotics systems 中的 model assumptions 会通过 simulator、collision geometry、world model、policy context、training objective、data-generation contract、workflow/export contract、sensor/rendering contract、training-runtime contract 和 benchmark design 进入 downstream decisions 与 reported performance；这些 assumptions 在温和场景里可能被 success rate 掩盖，但在 contact-rich dynamics、long-horizon rollout、heterogeneous data、unseen task composition 和 sim-to-real transfer 中会变成 first-order failure source。[[CollisionGeometryForRobotSimulation]] 把这条链条进一步推到 contact pipeline 上游：sphere/capsule/cylinder、convex hull、ACD、SDF 或 differentiable primitives 会改变 generated contact points、normals、clearance 和 solver constraints。[[VIRAL]] 的 visual sim-to-real case 强化了这个判断：RGB-based humanoid loco-manipulation 的 transfer 不是单一算法问题，而是 privileged teacher、visual student、domain randomization、real-to-sim alignment、compute scaling 和 failure analysis 的耦合系统。[[GRAIL]] 又把这条链条推到 demonstration source：generated video prior 只有在 known 3D assets、metric camera/scale/depth、interaction-aware reconstruction、retargeting 和 physics executability 都成立时，才会变成 robot-useful data。[[AGILE]] 则把 humanoid RL 的 workflow/export contract 拉进同一张图：joint axes、reward activation、motion diagnostics、I/O descriptors 和 policy export mismatch 也可能制造 silent deployment failures。[[RoboticsSimulationInfrastructure]] 把这条链条再往前推：task/API、asset management、renderer、visualizer 和 ML integration 会决定什么 scene 容易表达、什么 failure 容易看见、什么 resource 留给 training。[[UniLab]] 进一步把 training runtime 拉进 infrastructure layer：collector/learner placement、replay boundary、H2D transfer、buffering 和 synchronization 会决定 robot RL 的 end-to-end wall-clock efficiency。[[RTXSensorSimulationPipeline]] 进一步把 renderer/sensor output contract 具体化：在 ovrtx 里，OpenUSD composition、RenderProduct/RenderVar schema、DLPack tensor mapping、GPU synchronization 和 warm-up policy 都会影响 observation tensors 的含义与可靠性。

这条判断把多类材料连成一条主线。[[ContactModelsInRobotics|contact models in robotics]] 说明 low-level contact law 与 [[ContactSolvers|solver]] 不是 implementation detail，而是 task-level modeling assumption；[[WorldModelsForEmbodiedAI|world models]] 说明 learned latent dynamics 也是 simulator，只是 failure 可能表现为 temporal drift、weak physical consistency 或 misleading futures；[[VisionLanguageActionModels|VLA]] 和 [[RobotContextConditioning|context conditioning]] 说明 robot foundation model 的 behavior mode 由 prompt、metadata、subgoal image 和 control mode 选择；[[LatentDynamicsActionModels|latent dynamics action models]] 与 [[InverseDynamicsModels|inverse dynamics models]] 说明 data quality 的影响取决于 training objective 如何分配 data role、如何把 visual transition 变成 action representation；[[TaskGeneralistPolicyEvaluation|task-generalist policy evaluation]] 说明 benchmark predicates、language variants 和 perturbation protocol 决定哪些 failure 会被看见；[[HumanoidRLWorkflow|humanoid RL workflow]] 说明即使 policy/reward 看起来正常，development contract 仍可能决定 sim-to-real 是否可靠；[[RoboticsSimulationInfrastructure|simulation infrastructure]] 与 [[RTXSensorSimulationPipeline|sensor rendering pipeline]] 说明 scene authoring、assets、rendering outputs 和 ML loop 也会变成 research workflow 的 hidden assumptions。[[EmbodiedGen]] 进一步说明 generated world 只有跨过 metric geometry、collision、physical parameters、semantics、affordances、interfaces 和 executable validation 这些 gates，才从 3D content 变成 robot-learning infrastructure。

| Collision geometry choices 为什么会影响 robot simulation？ | Collider representation 决定 contact candidates、contact points、normals 和 clearance；primitive、single hull、ACD、SDF 与 differentiable primitive metrics 在 fidelity、speed、editability 和 gradients 上取不同 tradeoff。 | [[CollisionGeometryForRobotSimulation]], [[ApproximateConvexDecomposition]], [[DifferentiableCollisionDetection]] |
| Visual sim-to-real 如何跨过 reality gap？ | VIRAL 说明 transfer recipe 至少要同时处理 visual distribution、camera geometry、hand dynamics、distillation distribution 和 compute scale；domain randomization 与 real-to-sim alignment 是互补项，不是替代项。 | [[VisualSimToReal]], [[VIRAL]], [[SimulationRealityGap]] |

| Humanoid RL 从训练到硬件怎样减少 silent failures？ | AGILE 把 verification、training、evaluation 和 deployment export formalize 成 workflow contract；关键不是单个新算法，而是提前检查 MDP、记录 run、做 deterministic scenario diagnostics，并用 I/O descriptors 避免 export mismatch。 | [[HumanoidRLWorkflow]], [[AGILE]], [[SimulationRealityGap]] |
| 当前证据最薄弱在哪里？ | strongest evidence 来自 source-specific benchmark 和 ablation；weakest link 是跨系统、跨机器人、跨 benchmark 的 independent replication 与真实部署因果验证。 | [[research-questions|Research Questions]], [[SimulationRealityGap]] |

## 关键张力

- Exactness vs usability：更接近 rigid contact reference model 的 formulation 物理目标更清楚，但 numerical difficulty 更高；relaxation、heuristic per-contact handling 和 warm-starting 提高可用性，也可能引入 artifacts。见 [[ContactComplementarity]]、[[ContactSolvers]]。
- Collider fidelity vs throughput/editability：single hull 和 primitives 快且易编辑，但可能填满 task-critical concavity；ACD/SDF 更保真但增加 preprocessing、runtime cost 和 contact complexity；differentiable primitives 给 gradients，但不是完整 contact dynamics。见 [[CollisionGeometryForRobotSimulation]]、[[ApproximateConvexDecomposition]]、[[DifferentiableCollisionDetection]]。
- Fidelity vs decision relevance：world model 生成 future frames 的视觉质量不等于控制价值；对 embodied AI，更关键的是 latent state、rollout horizon、action conditioning 和 downstream policy/evaluation 是否受益。见 [[WorldModelEvaluation]]。
- Data scale vs data role：更多 robot/human/video data 不自动带来 better policy；π0.7、LDA-1B、Seer 和 DeFI 都把 heterogeneity 的关键放在 conditioning、objective routing、future-conditioned inverse dynamics 或 inverse-dynamics proxy task，而不是单纯扩大 BC corpus。见 [[RobotContextConditioning]]、[[LatentDynamicsActionModels]]、[[InverseDynamicsModels]]。
- Benchmark coverage vs deployment confidence：RoboLab 这类 benchmark 能系统暴露 task-generalist policy 的 failure modes，但它仍是 measurement substrate；真实 deployment 还需要验证 sim failure factor 是否在 hardware 上 causal。见 [[TaskGeneralistPolicyEvaluation]]、[[SimulationSensitivityAnalysis]]。
- Structure vs hackability：config-driven simulation APIs 更利于 serialization、governance 和 consistent assets；direct Python APIs 更利于快速 authoring 和 experimentation。这个 trade-off 会影响 human developers、LLM scene generation 和 benchmark maintainability。见 [[RoboticsSimulationInfrastructure]]。
- Visual plausibility vs simulation readiness：生成模型可以产出看起来合理的 mesh/scene，但 robot learning 还要求 metric scale、colliders、physical parameters、joint semantics、affordances、task constraints 和 stable interfaces；任何一层缺失都可能让内容无法执行或产生 silent mismatch。见 [[SimulationReady3DWorldGeneration]]、[[EmbodiedGen]]。
- Sensor contract vs opaque rendering：把 sensor output 写成 `RenderProduct` / `RenderVar` / DLPack contract 可以改善 reproducibility、debugging 和 ML integration；但 observation tensor 的物理真实性仍取决于 sensor model、material semantics、calibration 和 validation。见 [[RTXSensorSimulationPipeline]]。
- GPU-resident coupling vs heterogeneous overlap：把 physics、rollout 和 learning 放在 GPU execution path 上很有效，但也可能制造 accelerator contention、CUDA stack dependence 和 replay-memory pressure；CPU-batched simulation + GPU learning 只有在 runtime 能把 collection / packing / H2D hidden behind learner update 时才成立。见 [[HeterogeneousRobotRLTraining]]。
- Algorithmic novelty vs workflow correctness：AGILE 提示 humanoid RL 的失败可能来自 workflow boundary，而不是 policy architecture 本身；joint order、history buffer、action scaling、reward activation 和 deterministic motion diagnostics 都需要进入 development contract。见 [[HumanoidRLWorkflow]]、[[AGILE]]。
- Generated prior vs metric grounding：GRAIL 把 VFM 当作 interaction prior，而不是 4D truth；known assets、camera、depth 和 morphology 可以降低 reconstruction ambiguity，但 VFM artifacts、contact force、retargeting 和 hardware dynamics 仍要单独验证。见 [[AssetConditionedHOIGeneration]]、[[GRAIL]]。
- Differentiability vs physical truth：可微 simulation 与 differentiable rendering 让 gradients 可用，但 contact relaxation、spurious forces 或 learned dynamics artifacts 可能污染 gradient direction。见 [[DifferentiablePhysics]]、[[SimulationRealityGap]]。

## 下一步缺口

- 补充 independent replication 或 follow-up sources：π0.7、LDA-1B、RoboLab、VIRAL 和 AGILE 都有强 source-specific claims，但需要更多外部复现、失败案例或对比评测。
- 追踪 AGILE/WBC-AGILE 的后续 hardware reports：当前 source 对 workflow、evaluation 和 ablations 很有价值，但 real-world quantitative tracking metrics 与 perception-driven humanoid manipulation 仍是明显缺口。
- 追踪 GRAIL project page、code、dataset 和 follow-up reports：当前 source 已给出 arXiv v1 的 pipeline、losses、runtime、benchmarks 和 real-world success rates，但 release artifacts、failure filtering rate、VFM version drift 与 independent replication 仍是关键缺口。
- 追踪 EmbodiedGen V2 的 code/data release、跨 simulator dynamics validation、physical-parameter ground truth、affordance end-to-end benchmark 和 companion policy-scaling studies；当前论文证明了 pipeline viability，但没有把 simulation readiness 升级成 physical equivalence guarantee。
- 给 world model papers 建立更结构化 ingest metadata：horizon、input modality、action coupling、closed-loop validation、real-robot validation、benchmark、code/data availability。这个需求来自 [[WorldModelEvaluation]] 与 [[AwesomeWorldModels]]。
- 追踪“latent dynamics + runtime context steering + predictive inverse dynamics”是否会合流：LDA-1B 的 objective routing、π0.7 的 runtime steering、Seer 的 end-to-end PIDM 与 DeFI 的 decoupled GFDM/GIDM 看起来互补，但当前 sources 还没有证明组合系统。
- 对 simulation reality gap 保持多层解释：gap 不只来自 physics engine 参数，也可能来自 learned dynamics objective、policy prompt/context、workflow/export contract、sensor/rendering contract、benchmark predicate 和 evaluation aggregation。见 [[SimulationRealityGap]]。
- 补充 simulation infrastructure official sources：ManiSkill、Isaac Lab、MuJoCo Lab、SAPIEN 和 Viser 的 docs/repo snapshots，可以把当前 blog-level design lens 转成更可维护的 implementation notes。见 [[RoboticsSimulationInfrastructure]]。
- 补充 robot RL training system sources：MuJoCoUni、MotrixSim、UniLab repo、mjlab / MjWarp、MuJoCo Playground、Isaac Lab 和 ManiSkill3 的 official docs/repo snapshots，可以把 [[HeterogeneousRobotRLTraining]] 从单篇 systems paper 扩展成可比较的 runtime taxonomy。
- 补充 engine-specific collider benchmarks：同一 asset 的 capsule / primitive / convex hull / CoACD / VisACD / SDF collider 在 MuJoCo、Isaac Sim / PhysX、Bullet、Drake 中对 contact count、solver residual、training throughput、manipulation success 和 sim-to-real transfer 的影响仍缺系统比较。
