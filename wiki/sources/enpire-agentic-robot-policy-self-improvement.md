## 概览

ENPIRE 把真实机器人变成编码智能体可以反复调用的实验环境：先在人工反馈下建立重置、验收和操作边界，再冻结这些接口，让智能体修改策略代码或训练方法、运行实验并比较结果。它的核心是把现实试验组织成可重复的研究循环，既支持代码策略，也支持 BC、在线／离线 RL 及其组合。（§1–2）

完整阅读 v2 HTML 正文、参考文献及附录 A–D；以下为论文报告与明确标出的解释，未核查仓库实现或复现。官方项目页标注 CoRL 2026 接收；本页实际阅读的是 2026-09-20 的 arXiv v2，不将项目演示当成另一组独立实验。

## 两阶段设计及接口

第一阶段的 EN（Environment）需要人工提供任务目标、成功／失败样例及反馈。智能体利用分割、位姿跟踪、规划与机器人接口，建立三项基础：限制操作范围的执行约束、返回任务结果的验证器、回到随机初态的重置程序。论文中的自动化是这些组件完成后开始的，不能省去这笔前期工程与人工成本。（§2.1、附录 A）

例如扎带验证器结合顶置与侧面图像，检查带身是否穿过扎带头并伸出足够长度；多视角用于减少单视角遮挡带来的假阳性。其开发使用人工标记的成功／失败数据，目标同时包含判断准确度和低于150毫秒的延迟。插针验证则结合视觉对齐、末端高度和力矩信息。验收器固定后提供后续优化信号；它的误差仍可能决定系统优化到什么行为。（附录 A.2；末句为解释）

第二阶段分为 PI（Policy Improvement）、R（Rollout）、E（Evolution）。PI 的可写面是策略与训练代码；R 负责物理执行、视频、轨迹、奖励与错误；E 让不同机器人上的智能体通过 Git 共享、选择或合并有收益的方案。论文称第二阶段环境接口不可修改，不能据此写成“智能体任意改验收标准”。（§2.2）

```mermaid
flowchart LR
  A[人工样例与反馈] --> B[构建并核验环境接口]
  B --> C[冻结重置与验收接口]
  C --> D[提出策略或训练代码修改]
  D --> E[真实机器人执行并记录]
  E --> F[比较结果与分析失败]
  F --> D
  F --> G[经 Git 共享有效方案]
  G --> D
```

这是按方法重画的教学流程。重置会把机器人送到插针、插卡等精密阶段的起点，因此测得的学习效率主要针对这些瓶颈，不能直接解释为从任意杂乱状态自主完成整个生产任务。

## 一次实验的数据与控制流

每个站点包含双臂 YAM、相机、GPU 工作站和编码智能体。局部 FastAPI 暴露 `/start`、`/restart`、`/home`；其中 `/restart` 分配新的轨迹目录，不能误解为把物理世界或所有代码恢复到旧版本。Push-T 另有避开相机遮挡后恢复动作的接口。（附录 B.1）

智能体写入策略／训练修改，启动试验；执行层按回合保存观测张量、同步视频、动作来源与结果。RL 集成采用分离的执行层、学习器、动作服务，磁盘采集器读取已完成回合，将 RL 轨迹和人工示范分别送入在线与示范缓冲，再混合训练。策略推断30 Hz、底层控制100 Hz、编码智能体的实验迭代是三个时间尺度。（附录 B.2–B.5）

迁移实验将插针研究中的经验写成 Markdown，再用于 GPU 插卡；原始轨迹、检查点和隐藏日志被移除。持久迁移的是总结知识，不能把它说成已证实跨任务迁移了全部训练状态或自动改进算法本身。（§3.4、附录 B.1）

## 实验与预算怎么读

| 实验及定位 | 论文报告 | 必须保留的协议 |
| --- | --- | --- |
| 真机操作，§3 | 标题性结果达到约99% | 每个子任务允许最多8次、依赖前次失败的重试；不是一次尝试成功率，也不是8个独立样本的最佳值 |
| 插针，§3.2 | 以连续50回合成功为优化目标；智能体探索 BC、RL、正则与批大小等 | 有固定验证器与精密阶段重置；论文没有给出独立重复研究运行的完整置信区间 |
| 机器人数量，§3.3 | Push-T 从1台到8台，达到目标约5小时缩短到2小时；插针从超过1.5小时缩短到约40分钟 | 增加机器人、智能体与 token 资源，不能声称同总成本更省 |
| RoboCasa，附录 D | 每任务40个固定种子／布局／风格三元组，方法共用初态与成功判据 | 标准脚本只执行一次，禁用重置和目标真值接口；此协议与真机8次恢复协议不同 |
| 简化 Push-T 消融，附录 C | 原生视觉较快；无视觉版本先于外接视觉函数版本完成 | 使用放宽成功区域的简化任务，不是主任务总体排名 |

资源账本值得单独学习。按论文定义，机器人利用率是研究总时长中实际运行实验的比例；token 指标在§2.2表述为消耗量，在§3.6具体采用每分钟 token。比较时应同时报告总 token、输入／输出／缓存构成、到达目标时间、机器人数量和实际实验时间，不能单看一个利用率。论文观察到8智能体下 token 增长超过线性趋势，单台机器人利用率反而降低，原因包括阅读日志、等待推理与交流分支。（§3.6、§4、附录 C.2）

## 与机器人 Harness、RSI 的关系

[[gap-graph-as-policy|GaP]] 主要在仿真中修改执行图；ENPIRE 把真实执行和自动重置作为优化循环本身。[[simex-simulation-integrated-robotics-autoresearch|SimEX]] 则用少量真实试验指导更多仿真修复；两者的重置成本、反馈频率与可编辑对象不同。SimEX 文中的 ENPIRE* 是统一接口下的重实现，不等于本论文原始系统的全面复现。

**我们的解释：**ENPIRE 已把部分算法研发交给智能体，包括更改训练代码；但“修改训练算法”与“改进者在后续新任务上变得更有效”仍是不同证据。需要固定起点、数据和预算，对比新旧改进程序，才能支持更强的递归改进主张。验收器、重置器和底层物理接口也仍由第一阶段与人工约束界定。共享比较见 [[PhysicalRecursiveSelfImprovement|Physical RSI 的证据要求]]。
